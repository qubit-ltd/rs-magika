## 3. 路线选择

选择“局部兼容修复先行，异步迁移依现有设计门禁执行”。MAGIKA-002/003/004 可在当前契约完成，不必等待跨库迁移；MAGIKA-001 始终保留在总验收中，依赖未满足时明确报告未完成。

不选择在 0.18 中加入私有线程池、独立取消协议或强绑 Tokio：会重复既有 0.19 规划并增加后续迁移成本。也不把 rs-operation、rs-command、rs-fs 等全链实现无条件并入本次修复：本命令没有授权实施跨库工程；上游实现作为明确的外部交付依赖。未来执行命令若授权跨库工作，可在相关仓库按各自设计完成前置，不以空接口或关闭测试绕过门禁。

## 4. MAGIKA-002：有限连续中断重试

维持现有可重试条件，仅增加内部常量 `MAX_CONSECUTIVE_INTERRUPTED_RETRIES = 8`，不新增公共配置/API。每次底层 read_at 最多首次尝试加 8 次重试，即第 9 次仍返回可重试中断时，直接返回该 FsError，经原路径映射并保留 source。非安全中断及普通错误继续立即返回。

一次成功的正进展读取结束当前 retry helper；下一段读取重新计数。0 字节仍由 exact-read 层处理为 UnexpectedEof。预算保持现有“逻辑采样请求预留一次”语义，分段和无进展中断不重复扣字节；新增尝试次数边界独立限制调用量。不得声称可重试中断绝对未读取网络字节，也不得宣称这是时间期限。

与旧 0.19 设计“每次重试累计计费”的文字冲突时，实施阶段明确协调为：成功读取的有效采样字节受原预算约束，无进展尝试受重试上限和操作期限约束，不双重扣逻辑请求。禁止静默引入新的预算含义。

同步/异步测试覆盖连续 8 次中断后成功、第 9 次仍中断失败、错误 source/effect 保留、成功短读后计数重置、普通错误及不确定中断不重试、预算不被重试绕过。持续中断测试必须有外部超时保护，避免旧实现无限挂起测试进程。

## 5. MAGIKA-003：真实异步等待测试

测试支持层采用 Arc<Wake> 与线程 park/unpark，或现有等价的唤醒驱动执行器。poll 返回 Pending 后只在收到通知时继续；使用原子通知标志防止 wake-before-park 丢失，采用单调截止时间失败退出，不使用 sleep/yield 循环代替唤醒。测试执行器仅用于测试，不进入生产依赖。

增加 gate fixture：首次 poll 登记 waker 并返回 Pending，另一个控制端释放后调用 wake；释放前不得读取或完成。分别覆盖 stat/open/read 中真实暂停、wake-before-wait、重复 wake、错误恢复、等待 future 被丢弃后资源释放。使用每次 poll 后更新的 waker，验证旧 waker 不被错误沿用。显式用“Pending 但不 wake”的受控 future 验证测试驱动按超时失败，而非自行轮询成功。

复用测试工具但保留 src 单元测试与根 integration test 的组织边界；优先共享同一测试支持实现，若跨边界复用需要源码重定向，则各自保持小型驱动，避免违反测试文件组织规则。现有预算/ETag/分段/对象一致性用例保留。

## 6. MAGIKA-004：细化支持契约

本轮选择记录并锁定当前行为，不扩展 provider-path 的媒体读取或细化能力。

| 入口 | 当前 classifier 行为 |
| --- | --- |
| 高层完整 bytes 检测 | 满足配置和 MIME 映射条件时可调用 classify_content |
| 高层 seekable reader 检测 | 满足条件时可调用 classify_reader，恢复游标 |
| 高层本地 file 检测 | 满足条件时可调用 classify_file |
| detect_path / detect_async_path | 当前不调用 classifier，包括完整读取的小对象 |
| 直接 MimeContentBackend | 返回内容候选，不承诺高层选择和媒体细化 |

更新 `README.md`、`README.zh_CN.md`、`doc/user_guide.md`、`doc/user_guide.zh_CN.md` 及 builder/provider Rustdoc，说明启用 classifier 不代表所有入口均细化。顺带纠正相关 backend Rustdoc 把候选元组说成 Option/已选择 MIME 的描述；仅处理与本轮契约相关的文字。

测试使用可计数 classifier，在满足精细检测映射与开关条件的同一 detector 上，对完整内容入口验证正向调用，对 session/legacy/read_all 的同步与异步 provider 路由断言零调用。不依赖机器安装 ffprobe；不得把采样 prefix 传给 classify_content，也不为细化额外绕过 max_bytes 全量读取。

## 7. MAGIKA-001：受管理异步迁移

### 前置与范围

复用既有 0.19 设计中已定义的职责划分与公共操作协议。开始前固定 rs-operation 已验收提交，核对公共 scope、资源持有、结果与释放分离、取消、期限、shutdown；核对 fs 0.4/mime 0.22 及所需适配器的实际接口和消费测试。缺失时停在该任务，继续独立局部任务，不伪造迁移完成。

### 最小落地形态

默认一个推理 session 延续串行语义。线程内部创建、使用及销毁 Session；detector 和 provider 共享 runtime，不按请求初始化模型。特征计算与推理分离，前台异步 future 只驱动 provider I/O 和等待通知，不在 poll 内执行同步初始化、特征计算、模型锁等待或 native 推理。

保留现有 sampling 与 MIME 映射算法；特征 worker 通过容量为 1 的 range 桥向前台请求样本。请求在采样前准入，worker 数、队列任务数和 owned 数据有上限，沿用现有 0.19 设计中的显式默认配置，不增加自动 batch、多模型扩容或缓存。Features 必须实际通过 Send 编译断言，Session 无须跨线程。

取消关闭桥并唤醒 worker；队列满也能传递停止信号。native 推理不可强杀，业务停止结果与实际资源释放分开，许可必须保持到 worker 停止访问资源。worker panic、通道断开、初始化失败均返回明确错误并释放资源，不转成 Ok(None)，不自动无限重建。复用公共 supervisor，不新建另一套通用注册表。

同步调用等待同一 runtime 作业，允许阻塞；异步字节/reader/provider/构造等入口显式实现或按新上游契约返回 Unsupported，不继承同步阻塞默认实现。provider 身份、稳定 repository 默认选择、inventory 发现方式、未知分类、预算和错误分类保持原语义。跨阶段借用不得逃逸；已 owned 内容同样受容量预算约束。

### 兼容性与迁移

MAGIKA-002/003/004 不要求破坏公共签名；002 会使过去无限等待的持续中断调用返回原始错误，须写明行为变化。

001 若采用现有跨库托管接口需要 0.19 破坏性版本，与 mime 0.22/fs 0.4 配套。受影响的是构建 detector/provider 的应用和实现/使用 MIME backend 的集成方；本地检索未发现其他 rs-* 的直接生产依赖，不等于外部用户不存在。迁移文档须给出可编译的共享 supervisor/runtime 启动、prepare、scope 检测和 shutdown 示例，以及现有 inventory 路径的限制或兼容办法。按实际上游接口更新，不照抄草案签名；不主动升级 magika/ort，不改变进程全局 runtime 加载先后契约。

## 8. 验收与风险

四项分别验收：002 有界尝试且错误保真；003 有真实 Pending/wake 与有限等待；004 双语文档和正反向调用测试一致；001 通过上游门禁、受控阻塞心跳测试和共享 runtime 生命周期测试。局部任务完成不能代表四项全部完成。

001 至少覆盖初始化/特征/推理闸门阻塞时心跳推进、容量满、取消前后竞争、native 返回前资源仍持有、panic/关闭、ruled 不占 session、同步/异步结果一致。性能记录冷启动、热调用、排队、模型内存和取消到释放延迟；不预设吞吐提升，不制定无基线支撑的性能数字门槛。

最终由集成任务运行仓库实际 ci-check.sh、全 feature 测试、严格 Rustdoc、文档消费者及 coverage 等适用门禁。保留既有阈值和用例，允许为失败、CI 错误或覆盖率不足修改必要源码和测试，包括已有基线问题；记录原因和范围，禁止通过降低阈值、忽略错误或排除代码来过关。

本轮不新增英文设计副本、GPU、多进程、事件总线或无关风格重构。上述非目标是最小实现选择，不是用户新增的永久禁令。
